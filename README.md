# Meeting Dynamics

対面会議で各参加者のスマートフォンのマイクから**音量・VAD（発話状態）の特徴量だけ**を扱い、発話量を見える化する React + TypeScript アプリです。音声の録音・送信・保存は行いません。

公開 URL: https://kkodamalab.github.io/meeting-dynamics/

## 使い方

1. ホストがトップ画面で話者数、部屋レイアウト、集計オプションを選び「セッションを作成」します。
2. 参加者ごとに表示名を設定し、参加リンク（QR 化して共有可能）をスマートフォンへ渡します。
3. 参加者はリンクを開き、名前を入力して「マイクを許可」を選びます。マイク許可には HTTPS または localhost が必要です。
4. ホストが座席をドラッグ配置し、計測を開始します。終了後、概要と CSV/JSON を確認できます。

## 技術と制約

- Vite / React / TypeScript。GitHub Actions で GitHub Pages へデプロイします。
- GitHub Pages の静的画面から、別途デプロイする Cloudflare Workers + Durable Objects 中継へ接続します。
- 本番で端末間同期を使うには、下記の中継デプロイと接続先URLの設定が必要です。
- 将来候補: 端末キャリブレーション、WebRTC DataChannel、曖昧話者検出、感情推定モデル、認証付きセッション。

## リアルタイム中継と公開設定

この版は Cloudflare Workers + SQLite Durable Objects の WebSocket 中継を使います。
GitHub Pages は画面を配信し、参加者の音量/VAD・登録状態だけを中継します。
ランダムな発話デモは集計に使いません。全端末で同じ中継URLを使用します。

### ローカル開発・テスト

Node.js 22.18 以降または 24 が必要です。

```sh
npm ci
npm run relay:dev  # ターミナル1: 127.0.0.1:8787
npm run dev -- --host 127.0.0.1 --port 5173 --strictPort  # ターミナル2
npm test           # ターミナル3: 起動済み中継に対する認証・同期・集計テスト
npm run build
```

トップ画面の中継URLに `http://127.0.0.1:8787` を入力します。
Python Playwright と Chromium がある環境では `python tests/browser_smoke.py` で
別ブラウザコンテキスト2台と実際の WebSocket 中継を使った画面連携テストを実行できます。
このテストのマイクは生成した波形です。スマートフォンの実機確認には代わりません。

### Cloudflare の本番中継

1. Cloudflare ダッシュボードでアカウントを選び、**Workers & Pages** を開きます。
   初回は Workers の `workers.dev` サブドメインを設定します。
2. **My Profile → API Tokens → Create Token → Edit Cloudflare Workers** を選択し、
   対象アカウントの **Account / Workers Scripts / Edit** と **Account / Account Settings / Read**
   があることを確認します。トークンはチャット・Git・公開フロントエンドに置かないでください。
3. 実行環境の安全な設定に `CLOUDFLARE_API_TOKEN` と `CLOUDFLARE_ACCOUNT_ID` を登録します。
   Account ID はアカウントの **Workers & Pages** 画面からコピーできます。
4. このリポジトリで `npm run relay:deploy` を実行します。
   `relay/wrangler.jsonc` が SQLite Durable Object の migration と `ROOMS` バインディングを作成します。
   有料プランの購入はこの手順に含みません。利用枠・プランの可否はアカウントで確認してください。
5. 出力された `https://meeting-dynamics-relay.<subdomain>.workers.dev` の `/health` にアクセスし、
   `{"ok":true}` を確認します。
6. GitHub リポジトリの **Settings → Secrets and variables → Actions → Variables → New repository variable**
   で **Name: `VITE_RELAY_URL`**、**Value: 上記の HTTPS URL（末尾の /health は除く）** を保存します。
   これは公開してよい接続先であり、認証トークンではありません。
7. **Actions → Deploy GitHub Pages → Run workflow → Branch: main → Run workflow** を実行します。
   **Settings → Pages → Build and deployment → Source** は **GitHub Actions** にします。
   完了後、公開URLで読み込まれた中継URLと通信を確認します。
   ビルド変数が未設定でも画面から実在するHTTPS中継URLを入力できます。

### 実機の確認手順

ホストでセッションを作成し、一括登録の座席上QRを別々のスマートフォン2台以上で開きます。
各スマホで表示名・マイク許可・参加登録を完了し、ホスト側の名前・登録済み・マイクOKを確認します。
「座席配置へ進む」で座席ドラッグ、テーブル移動・右下ハンドルによる変形・配置保存を確認し、計測画面へ進みます。
計測開始後、1台ずつ発話し、ホスト側の音量・VAD・発話時間が該当座席に反映されるか確認します。
停止・再開・終了・CSV/JSONを確認します。1台を閉じて切断表示、同じリンクで再接続を確認します。
スマホのバックグラウンド動作・省電力・マイク権限はOS/ブラウザに依存します。

座席配置はホストブラウザのローカルストレージへ人数・図形別に保存します。
セッションと座席リンクは推測困難な固有トークンを含みます。参加者だけに共有してください。
セッションの有効期限は12時間。中継は音声データを受け取らず、音量/VADと集計・表示名を保持します。
VAD・話者判定は下記のノイズフロア補正と適応方式を使います（声紋認識ではありません）。
曖昧な入力と同時発話は保留します。

## 音声診断・端末差の補正

計測画面の2パネル構成の下に、折りたたみ式の **音声診断** があります。
端末別の生RMS（ブラウザの音声処理後）、dBFS、ノイズフロア/SNR、VAD閾値、補正後音量、
受信時刻/連番、受信経過、遅延増分、実際の `track.getSettings()` と AudioContext 状態を確認できます。
受信がない・止まる・トラック消音・音声処理停止を、話者判定と分けて表示します。
遅延はクライアントの単調時計とサーバー受信経過の差による初回からの増分であり、絶対片道遅延ではありません。

計測前に全スマホの画面を開いたまま位置を固定し、各参加者の画面で次を行ってください。

1. **静音を測定（3秒）**：室内を静かにし、ノイズフロアを測定します。
2. **本人の発話を測定（3秒）**：その本人だけが通常の声で話します。他の参加者は静かにしてください。
3. **補正設定済み** と生RMS/補正後音量を確認し、全員の測定が完了してから計測を開始します。

RMSは浮動小数点で保持し、小さい入力を整数に丸めて失うことを避けています。
VADはノイズフロア+10 dBで開始、+6 dBで継続し、開始150ms・終了350msの平滑化を行います。
話者候補はノイズを差し引いた本人の基準発話に対する音量とSNRで比較し、250ms以上安定した候補に帰属します。
差が4 dB未満・双方が本人基準に近い強い発話・未測定・受信不足等は、無理に1名へ帰属せず保留します。
無音と話者不明は別集計です。CSV/JSONの既存列を維持し、`unknownSeconds` と `confidence` を追加しています。
`unknownSeconds` はセッション全体の値を各行に繰り返して記載するため、行間で合算しないでください。
`confidence` はその参加者に帰属した時間で重み付けした判定指標（0〜1）で、正答確率ではありません。
発話割合の分母には話者不明時間も含みます。

デフォルトでは echoCancellation/noiseSuppression/autoGainControl の **OFFを要求** します。
発話が双方で同程度になる場合や、AGCが入力ごとにゲインを変える場合、RMSだけの端末間比較は不安定になります。
ブラウザがOFF要求を無視することもあるため、診断の実際の設定を確認してください。
比較用チェックボックスは参加者画面にあり、変更にはマイク停止→再取得→再測定が必要です。
設定非対応は「不明／非対応」と表示し、OFF適用済みとは扱いません。
補正はマイク再取得で無効になり、再接続では現在の補正設定を再送信します。

同一の声を複数マイクが同程度に拾う場合や実際の同時発話は、音量特徴だけでは本人を確定できません。
この版は個人の声紋認識ではなく、補正と保留による誤帰属の抑制です。
画面位置、スマホとの距離、反射、OSの音声処理、環境音によって精度は変わります。
old/new実機での改善率は未測定です。診断を開いて両方の受信を確認し、本人が交互に発話する試験と同時発話を実施してください。

`npm test` はDSP・話者判定・時系列集計・通信・既存機能を検証します。
`python tests/audio_browser_smoke.py` は別Chromiumプロセスの10倍の感度差を持つ生成波形で、
静音/本人測定・適応VAD・低感度側の集計・折りたたみ診断・エクスポートを検証します。
`python tests/browser_smoke.py` はQR・座席操作・登録・CSV/JSON等の回帰検証です。
これらはスマートフォン実機の音響精度を証明しません。

## PC共通参照と比較研究（SMARTPHONE + PC REFERENCE）

新規セッションの「話者識別方式」は既定で SMARTPHONE ONLY（A）です。
SMARTPHONE + PC REFERENCE（B）を選択した場合だけ、「PCマイクを開始／再取得」から
PCマイクの権限を要求します。拒否時は理由を表示し、明示的にAへ切替できます。
自動切替はせず、PC欠損中のB結果はデータ不足となります。デバイス切替・再取得後は共同校正をやり直します。
PC MICは参加者・分母・個人の発話時間に含めません。

手順：PCとスマホを再読み込みし、新規セッションを作成→既存QRで全員を登録→
PCマイク開始→座席配置でPC MICを実位置に合わせて保存→共同キャリブレーション→計測。
校正はSTEP 1が全員無言3秒、以降は指定した本人だけ5秒ずつ発話します。
各STEPでPCと全スマホの特徴量を同時取得し、ノイズ床と話者×マイクの応答行列を保存します。
受信率70%未満、飽和、発話SNR 6dB未満は再測定です。位置・マイク処理を変更したら再測定してください。
相対座標は実距離を表しません。位置は信頼度の小さい補助で、音響的に曖昧な候補を選ぶためには使いません。

`src/study.ts` が整列・比較・集計・評価の独立モジュールです。
取得時刻は単調時計に壁時計アンカーと最小RTTから推定した時計差を加えます。
サーバー時刻へ補正し、100ms窓・350ms待機・150ms許容範囲で整列します。
不確かさ200ms超、取得から2秒超、将来200ms超、重複／逆順シーケンスは整列対象から外します。
これはネットワーク遅延の推定であり、通信到着順による音源定位や音速差の測定ではありません。
各窓には実際に選択した取得時刻、受信時刻、連番が残るため、フレームの再利用／欠損も確認できます。

Bはノイズのエネルギーを差し引いた対数音量ベクトルを中心化し、本人の声量の共通変動を除いて
話者ごとの校正ベクトルとRMSE距離で比較します。3窓のエネルギー平滑化、SNR、候補間距離差を使います。
複数話者のエネルギー混合モデルに近い場合は同時発話候補、差が小さい場合は不明とします。
PCが全員から等距離でもスマホ応答が異なれば区別できますが、全応答が同じなら区別できません。
Aも同じ窓・同じ入力から既存の補正音量判定で計算し、Bで収録したデータからAを比較できます。
PCを追加するだけで精度が上がるとは保証しません。

時間は排他的な「個人帰属／話者不明／無音／データ不足／同時発話候補」に分けます。
総発話時間（VAD時間）=個人帰属＋不明＋同時発話候補、計測時間=総発話＋無音＋不足。
同時発話候補は個人へ重複加算しません。割合の分母は総発話時間で、PCは加えません。
発話回数は本人の帰属区間の持続時間を基準に、既定350ms以下の短いギャップを統合し、
累積帰属300ms以上で1回とします。短い帰属時間は隠さず発話時間に残し、回数だけは数えません。
別の本人へ帰属した発話が間にある場合は別区間です。両閾値は研究用詳細で設定できます。
計測は100ms量子化で末尾100ms未満を含まず、停止・再開時の休止は集計しません。
旧セッションの集計は保持しますが、当時未取得の時系列は復元できず、Bの過去区間は不足とします。

研究用詳細で評価テストモードとデータ由来（実機／模擬）を指定し、各発話区間の開始時に
正解の参加者を選択して記録します。未選択は無音、複数選択は同時発話です。
例：A10秒→無音5秒→B10秒→無音5秒→A+B5秒。
データ由来は利用者の申告で、自動の実機検証認定ではありません。
評価はラベルのある窓だけを対象に、VAD適合率/再現率、単独話者正答率、誤帰属率、
単独発話時間MAE、発話回数MAEを算出します。保留は誤帰属に含めず正答にも含めません。
同時発話の個人時間は重複計上しない定義のため、時間MAEの正解側も単独発話だけです。
分母0は未評価（null）で、精度100%とは表示しません。

既存CSV/JSONの参加者行を維持し、方式・PC状態/設定・校正・不足/同時発話時間を追加しました。
「研究データJSON」は時系列、校正、PC/座席位置、区間、A/B比較、正解ラベル、評価を含みます。
「特徴量CSV」はメタデータ行＋各窓の特徴量/両方式/ラベル行です。音声波形は送信・保存しません。
PC入力デバイスIDはブラウザ内だけで使い、共有する実設定はAGC等の処理設定に限定します。
表示名、座席、音声特徴量、ラベルは研究用ファイルに含まれるため、参加者に共有・保存範囲を説明してください。
時系列はDurable ObjectのSQLiteへ分割保存し、エクスポートはストリームで返します。
セッションは12時間で削除。1計測は最大60分または特徴量32MiBで明示停止し、データを黙って間引きません。
リセットは取得済み時系列を消去します。必要な結果は先に出力してください。
